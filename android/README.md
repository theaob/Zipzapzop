# ZipZapZop for Android

A WebView wrapper around the same game as the web version (`../web/page.html` + `../web/engine.js`), with fonts bundled so it plays offline. `make_page.py` writes `assets/index.html` from the web source on every build, so game changes only need to be made once.

## Gradle build (ads, purchases, Play release)
GitHub Actions (`.github/workflows/android.yml`) runs `./gradlew assembleDebug bundleRelease` on every change and uploads the debug APK and the release AAB as artifacts. When the release keystore secrets are set, the debug APK is signed with the upload key too, and the run's summary shows its SHA-1, so a test APK installed from GitHub can sign in to Play Games once that SHA-1 is an Android credential in the Play Games project. It can't be installed over a copy from Play (different signature); uninstall that first. Locally, with the Android SDK installed: `./gradlew assembleDebug`.

- Package `com.onurbaykal.zipzapzop`, min Android 7.0 (API 24), target and compile API 36.
- Ads: only AdMob rewarded ads that the player asks for, after Google's consent form (UMP); no ads between puzzles. Hints: 3 free a day across Daily and Ladder, then one finished rewarded ad per extra hint. Ladder energy: each new level costs 1 of 5, refilling 1 every 30 minutes, and a finished rewarded ad adds 3. Learn, the web version and Remove ads buyers have unlimited hints and energy. Code in `src-ads/.../Monetization.java`.
- Remove ads: one-time Play product `remove_ads`, re-checked on every launch so it survives reinstalls.
- Endless mode: separate one-time Play product `endless` (not included in Remove ads), checked the same way. Until it's owned, the Endless tab shows an unlock card. Builds without Play Billing (local `build-apk.sh`) and the web version have Endless unlocked. "Restore purchase" and "Privacy choices" are in the settings sheet.
- Monitoring: Firebase Analytics (events `puzzle_start`, `puzzle_solve`, `tutorial_complete`, `rewarded_ad_start` / `rewarded_ad_result` with `purpose` hint or energy, `energy_empty`, plus Firebase's automatic ones) and Crashlytics (crashes and page JavaScript errors), in `src-ads/.../Telemetry.java`. Both stay off until the consent flow allows them. They are built in only when `google-services.json` is present; CI writes it from the `GOOGLE_SERVICES_JSON` secret.
- Play Games (Services v2): sign-in at launch (Play Games signs returning players in; anyone else gets the sign-in prompt at launch, and after closing it launches stay quiet for 7 days), achievements and leaderboards, in `src-ads/.../GameServices.java`, with Sign in / Achievements / Leaderboards buttons in the settings sheet. The page works everything out from saved progress and resends it after each solve and on sign-in. Built in only when `res/values/games-ids.xml` is present; CI writes it from the `PLAY_GAMES_RESOURCES` secret, the XML from Play Console's Play Games "Get resources". The game looks IDs up by resource name and skips any that are missing:
  - Achievements: `achievement_first_steps` (first Daily or Ladder solve), `achievement_meadow_complete`, `achievement_ocean_complete`, `achievement_desert_complete`, `achievement_aurora_complete`, `achievement_volcano_complete`, `achievement_daily_trio` (all three dailies in a day), `achievement_week_streak` (a 7-day Daily streak; the weekly streak freeze can cover one missed day), `achievement_unassisted` (Hard daily with no hints).
  - Leaderboards: `leaderboard_ladder` (Ladder levels solved, 0 to 100, higher is better), `leaderboard_daily_easy`, `leaderboard_daily_medium`, `leaderboard_daily_hard` (time in milliseconds, lower is better).
  - Game Stats (Play Games profile, SDK 22.0+): the page sends `puzzleSolved` (`mode`, `puzzle`, `cells`, `seconds`, `hints`, `dailyStreak` = the streak shown in the header, freezes included) after each Daily or Ladder solve and `progressUpdate` (`currentProgress` = Ladder levels solved) once a session and when it rises. Events are matched by name, so they need no resource IDs, only the matching events and stats in Play Console. Endless (a purchase) and Learn send nothing, per Google's Game Stats rules.
- Android Auto (parked only): `android:appCategory="game"` and the `CAR_LAUNCHER` category put the game on the car screen while parked, on phones with Android 15 or newer. Android Auto hides it while the car moves because the activity has no `distractionOptimized` metadata; never add it. The phone's own screen stays portrait (`MainActivity.lockPhonePortrait`), car screens get any shape, and the page switches to a side-by-side layout on short landscape screens. To test, run the Desktop Head Unit at 800x480 (default), wide 1920x1080 with `marginheight = 596`, and portrait with `marginwidth = 878`. Play Console needs the Android Auto form factor opted in, and Google reviews the game against the car app quality guidelines for games.
- Debug builds always use Google's test ad IDs. Release builds use `ADMOB_APP_ID` / `ADMOB_REWARDED_ID` (hint ad unit) / `ADMOB_REWARDED_ENERGY_ID` (energy ad unit) / `ADMOB_BANNER_ID` (inline adaptive banner under the board) secrets (or `-PadmobAppId=` / `-PadmobRewardedId=` / `-PadmobRewardedEnergyId=` / `-PadmobBannerId=`), falling back to the test IDs.
- Release signing: set the `RELEASE_KEYSTORE_BASE64`, `RELEASE_KEYSTORE_PASSWORD`, `RELEASE_KEY_ALIAS` and `RELEASE_KEY_PASSWORD` repository secrets; without them the AAB is unsigned.

## Quick local build without Gradle (no ads)
```
sudo apt-get install aapt android-sdk-platform-23 dalvik-exchange zipalign apksigner
sh build-apk.sh        # -> build/zipzapzop-debug.apk
```
Uses `src-noads/` in place of the ads, billing, Firebase and Play Games code, so the APK has no ads, purchase, analytics or Play Games. Signed with `debug.keystore` (password `android`), created on first build and ignored by git. Launcher icons come from `make_icons.py`.
